# RF24_STM32 — nRF24L01(+) Driver for STM32 HAL

A pure-C, reusable port of the [nRF24/RF24](https://github.com/nRF24/RF24) Arduino library,
adapted for STM32 microcontrollers using the STM32 HAL.

The library lives entirely inside `Drivers/RF24/` and follows the same layout
as the ST-supplied HAL driver, making it easy to drop into any STM32CubeIDE project.

---

## Directory Layout

```
Drivers/
  RF24/
    Inc/
      nRF24L01.h        ← register map, bit names, SPI commands (no dependencies)
      RF24_STM32.h      ← public API + RF24_t handle struct
    Src/
      RF24_STM32.c      ← full driver implementation
Debug/
  Drivers/
    RF24/
      Src/
        subdir.mk       ← build rule (compile RF24_STM32.c)
```

---

## Hardware Requirements

- Any STM32 with an SPI peripheral (e.g. STM32F103 "Blue Pill")
- nRF24L01 or nRF24L01+ 2.4 GHz transceiver module
- **Decoupling capacitors on the radio's VCC/GND** (100 µF electrolytic + 100 nF ceramic) — this is mandatory; the radio draws spike currents that cause resets without them

---

## Wiring (STM32F103 Blue Pill)

| nRF24L01+ Pin | Blue Pill Pin | Notes |
|---|---|---|
| VCC | 3.3 V | Add decoupling caps! |
| GND | GND | |
| CE | PB0 | User-defined, any output GPIO |
| CSN | PA4 | User-defined, any output GPIO |
| SCK | PA5 | SPI1_SCK |
| MOSI | PA7 | SPI1_MOSI |
| MISO | PA6 | SPI1_MISO |
| IRQ | — | Not required (polling mode) |

> **Tip:** You can change CE and CSN to any available output GPIO by editing the `#define` values in `main.c`.

## Using the Library in Other Projects

This section gives complete, step-by-step instructions for dropping the RF24 library
into any STM32CubeIDE project, adapting it to a different STM32 family, and wiring it
into both Debug and Release build configurations.

---

### Step 1 — Copy the library files

Copy the entire `Drivers/RF24/` folder into the **root of the new project**, next to the
existing `Drivers/` folder:

```
YourProject/
  Drivers/
    CMSIS/
    STM32Fxxx_HAL_Driver/
    RF24/              ← copy this whole folder
      Inc/
        nRF24L01.h
        RF24_STM32.h
      Src/
        RF24_STM32.c
```

---

### Step 2 — Create the build rule file

Create the directory `Debug/Drivers/RF24/Src/` inside the new project and copy
`Debug/Drivers/RF24/Src/subdir.mk` into it.

> **What this file does:** `subdir.mk` is the makefile fragment that tells the
> compiler how to build `RF24_STM32.c`. It is **not** auto-generated by CubeIDE,
> so it will never be overwritten when you regenerate the project.

---

### Step 3 — Wire `subdir.mk` into the build system

STM32CubeIDE uses a three-file makefile chain. You need to touch two files:

#### 3a. `Debug/makefile` — add one `-include` line

Open `Debug/makefile`. Find the block of `-include` lines near the end of the file
(they include per-folder `subdir.mk` files). Add **one new line** after the last one:

```makefile
-include Drivers/RF24/Src/subdir.mk
```

The block should look similar to this afterwards:

```makefile
-include Core/Src/subdir.mk
-include Core/Startup/subdir.mk
-include Drivers/STM32F1xx_HAL_Driver/Src/subdir.mk
-include Drivers/RF24/Src/subdir.mk          # ← add this
```

#### 3b. `Debug/sources.mk` — add the folder to `SUBDIRS`

Open `Debug/sources.mk`. Find the `SUBDIRS` variable and add `Drivers/RF24/Src \`
to the list:

```makefile
SUBDIRS := \
Core/Src \
Core/Startup \
Drivers/STM32F1xx_HAL_Driver/Src \
Drivers/RF24/Src \                           # ← add this
```

---

### Step 4 — Add the include path to your application sources

Your application source files (e.g. `main.c`) need to find `RF24_STM32.h`.

**Option A — CubeIDE GUI (recommended; survives project regeneration):**

1. Right-click the project → **Properties**
2. Navigate to **C/C++ Build → Settings → Tool Settings → MCU GCC Compiler → Include paths**
3. Click the **Add…** button and enter: `../Drivers/RF24/Inc`
4. Click **OK / Apply and Close**

CubeIDE will persist this setting in `.cproject` and regenerate the include flag
automatically on every build.

**Option B — Edit `Debug/Core/Src/subdir.mk` manually:**

Find the `arm-none-eabi-gcc` compile command for your source files and append:

```makefile
  -I../Drivers/RF24/Inc \
```

Example (abbreviated):

```makefile
Core/Src/%.o ...: ../Core/Src/%.c ...
	arm-none-eabi-gcc "$<" ... \
	  -I../Core/Inc \
	  -I../Drivers/RF24/Inc \          # ← add this line
	  ...
```

> **Note:** Option B will be overwritten if CubeIDE regenerates the project. Prefer
> Option A for long-lived projects.

---

### Step 5 — Include the header and initialise

In your `main.c` (or any other source file), add inside the relevant `USER CODE` sections:

```c
/* USER CODE BEGIN Includes */
#include "RF24_STM32.h"
/* USER CODE END Includes */

/* USER CODE BEGIN PD */
#define RF24_CE_PORT   GPIOB
#define RF24_CE_PIN    GPIO_PIN_0
#define RF24_CSN_PORT  GPIOA
#define RF24_CSN_PIN   GPIO_PIN_4
/* USER CODE END PD */

/* USER CODE BEGIN PV */
static RF24_t radio;
static const uint8_t pipe_addr[6] = "Node1";
/* USER CODE END PV */
```

Inside `main()`, after `MX_SPI1_Init()` (or whichever SPI peripheral you use):

```c
/* USER CODE BEGIN 2 */
RF24_init(&radio, &hspi1,
          RF24_CE_PORT, RF24_CE_PIN,
          RF24_CSN_PORT, RF24_CSN_PIN);

if (!RF24_begin(&radio)) {
    Error_Handler();   // check SPI wiring / module power
}

RF24_setChannel(&radio, 100);
RF24_setPayloadSize(&radio, sizeof(uint32_t));
RF24_setPALevel(&radio, RF24_PA_LOW, 1);
RF24_setDataRate(&radio, RF24_1MBPS);
RF24_setCRCLength(&radio, RF24_CRC_16);
RF24_setAutoAck(&radio, 1);
RF24_setRetries(&radio, 5, 15);

// TX node
RF24_openWritingPipe(&radio, pipe_addr);
RF24_stopListening(&radio);

// -- OR -- RX node
// RF24_openReadingPipe(&radio, 1, pipe_addr);
// RF24_startListening(&radio);
/* USER CODE END 2 */
```

---

### Step 6 — Repeat for the Release build (optional)

If you use the **Release** build configuration, repeat steps 3–4 for the `Release/`
folder instead of `Debug/`:

1. Create `Release/Drivers/RF24/Src/` and copy `subdir.mk` into it
2. Edit `Release/makefile` — add `-include Drivers/RF24/Src/subdir.mk`
3. Edit `Release/sources.mk` — add `Drivers/RF24/Src \` to `SUBDIRS`
4. In `subdir.mk`, change the compile flags from Debug to Release:

   | Debug flag | Release equivalent |
   |---|---|
   | `-g3` | *(remove)* |
   | `-DDEBUG` | *(remove)* |
   | `-O0` | `-O2` or `-Os` |

---

### Adapting `subdir.mk` for a Different STM32 Family

`Debug/Drivers/RF24/Src/subdir.mk` contains STM32F1-specific flags. When using a
different STM32 family, edit these four things in the `arm-none-eabi-gcc` command:

| Line to change | F1 value | Example F4 value |
|---|---|---|
| CPU flag | `-mcpu=cortex-m3` | `-mcpu=cortex-m4` |
| Device define | `-DSTM32F103xB` | `-DSTM32F411xE` |
| HAL driver include | `-I../Drivers/STM32F1xx_HAL_Driver/Inc` | `-I../Drivers/STM32F4xx_HAL_Driver/Inc` |
| HAL driver legacy | `-I../Drivers/STM32F1xx_HAL_Driver/Inc/Legacy` | `-I../Drivers/STM32F4xx_HAL_Driver/Inc/Legacy` |
| CMSIS device include | `-I../Drivers/CMSIS/Device/ST/STM32F1xx/Include` | `-I../Drivers/CMSIS/Device/ST/STM32F4xx/Include` |
| FPU flags (F4/F7/H7) | *(not needed)* | `-mfpu=fpv4-sp-d16 -mfloat-abi=hard` |

The complete `arm-none-eabi-gcc` block from `subdir.mk` for reference:

```makefile
arm-none-eabi-gcc "$<" -mcpu=cortex-m3 -std=gnu11 -g3 \
  -DDEBUG -DUSE_HAL_DRIVER -DSTM32F103xB \
  -c \
  -I../Drivers/RF24/Inc \
  -I../Core/Inc \
  -I../Drivers/STM32F1xx_HAL_Driver/Inc/Legacy \
  -I../Drivers/STM32F1xx_HAL_Driver/Inc \
  -I../Drivers/CMSIS/Device/ST/STM32F1xx/Include \
  -I../Drivers/CMSIS/Include \
  -O0 -ffunction-sections -fdata-sections -Wall \
  -fstack-usage -fcyclomatic-complexity \
  -MMD -MP -MF"$(@:%.o=%.d)" -MT"$@" \
  --specs=nano.specs -mfloat-abi=soft -mthumb -o "$@"
```

---

### Multi-family HAL portability

By default `RF24_STM32.h` includes `stm32f1xx_hal.h`.
For a different STM32 family, define `RF24_HAL_INCLUDE` before the include or as a compiler flag:

```c
// Before the include
#define RF24_HAL_INCLUDE "stm32f4xx_hal.h"
#include "RF24_STM32.h"
```
```
// Or as a compiler flag
-DRF24_HAL_INCLUDE='"stm32f4xx_hal.h"'
```

## Quick Start

### 1. Include the header

```c
#include "RF24_STM32.h"
```

### 2. Declare a handle

```c
static RF24_t radio;
```

### 3. Initialise and begin

```c
RF24_init(&radio, &hspi1,
          GPIOB, GPIO_PIN_0,   /* CE  */
          GPIOA, GPIO_PIN_4);  /* CSN */

if (!RF24_begin(&radio)) {
    // Radio not found — check wiring
    Error_Handler();
}
```

### 4. Configure

```c
RF24_setChannel(&radio, 100);              // 2.500 GHz
RF24_setPayloadSize(&radio, 4);            // 4-byte fixed payload
RF24_setPALevel(&radio, RF24_PA_LOW, 1);   // -12 dBm
RF24_setDataRate(&radio, RF24_1MBPS);
RF24_setCRCLength(&radio, RF24_CRC_16);
RF24_setAutoAck(&radio, 1);
RF24_setRetries(&radio, 5, 15);            // 1500 µs delay, 15 retries
```

### 5. Transmit (TX node)

```c
static const uint8_t tx_addr[] = "TXnod";
RF24_openWritingPipe(&radio, tx_addr);
RF24_stopListening(&radio);

uint32_t payload = 42;
uint8_t ok = RF24_write(&radio, &payload, sizeof(payload));
```

### 6. Receive (RX node)

```c
static const uint8_t rx_addr[] = "TXnod";
RF24_openReadingPipe(&radio, 1, rx_addr);
RF24_startListening(&radio);

if (RF24_available(&radio)) {
    uint32_t payload;
    RF24_read(&radio, &payload, sizeof(payload));
}
```

## API Reference

### Initialisation

| Function | Description |
|---|---|
| `RF24_init(radio, hspi, ce_port, ce_pin, csn_port, csn_pin)` | Populate the hardware fields of the handle. Call before `RF24_begin()`. |
| `RF24_begin(radio)` | Reset and configure the radio. Returns `1` on success, `0` if chip not found. |

---

### Primary Interface

| Function | Description |
|---|---|
| `RF24_startListening(radio)` | Switch to RX mode. Call after `openReadingPipe()`. |
| `RF24_stopListening(radio)` | Switch to standby/TX mode. Call before `write()`. |
| `RF24_available(radio)` | Returns `1` if a payload is waiting in the RX FIFO. |
| `RF24_availablePipe(radio, pipe_num)` | Like `available()` but also reports which pipe received data. |
| `RF24_read(radio, buf, len)` | Read the next payload from the RX FIFO into `buf`. |
| `RF24_write(radio, buf, len)` | Transmit `len` bytes from `buf`. Blocking. Returns `1` if ACKed. |
| `RF24_writeMulticast(radio, buf, len, multicast)` | Like `write()` but `multicast=1` disables ACK for this packet. |

---

### Pipe Management

| Function | Description |
|---|---|
| `RF24_openWritingPipe(radio, address)` | Set the TX address (byte array of length `addr_width`). |
| `RF24_openReadingPipe(radio, number, address)` | Open pipe `0`–`5` for receiving. |
| `RF24_closeReadingPipe(radio, pipe)` | Close a reading pipe. |

---

### Configuration

| Function | Description |
|---|---|
| `RF24_setChannel(radio, channel)` | RF channel 0–125. Frequency = 2400 + channel (MHz). |
| `RF24_getChannel(radio)` | Read back the current channel. |
| `RF24_setPayloadSize(radio, size)` | Set static payload size 1–32 bytes. |
| `RF24_getPayloadSize(radio)` | Get static payload size. |
| `RF24_getDynamicPayloadSize(radio)` | Get the length of the next available dynamic payload. |
| `RF24_setPALevel(radio, level, lnaEnable)` | Set TX power. `level` is `rf24_pa_dbm_e`. |
| `RF24_getPALevel(radio)` | Get current TX power level. |
| `RF24_setDataRate(radio, speed)` | `RF24_1MBPS`, `RF24_2MBPS`, or `RF24_250KBPS` (nRF24L01+ only). |
| `RF24_getDataRate(radio)` | Get current data rate. |
| `RF24_setCRCLength(radio, length)` | `RF24_CRC_DISABLED`, `RF24_CRC_8`, or `RF24_CRC_16`. |
| `RF24_getCRCLength(radio)` | Get current CRC scheme. |
| `RF24_disableCRC(radio)` | Shortcut to disable CRC (only works if auto-ack is off). |
| `RF24_setAutoAck(radio, enable)` | Enable/disable auto-acknowledgement on all pipes. |
| `RF24_setAutoAckPipe(radio, pipe, enable)` | Enable/disable auto-ack on a specific pipe. |
| `RF24_setRetries(radio, delay, count)` | Retransmit delay (×250 µs + 250 µs) and count (0–15). |
| `RF24_setAddressWidth(radio, width)` | Address width: 3, 4, or 5 bytes. |
| `RF24_enableDynamicPayloads(radio)` | Enable dynamic payload length on all pipes. |
| `RF24_disableDynamicPayloads(radio)` | Disable dynamic payload length on all pipes. |
| `RF24_enableAckPayload(radio)` | Enable ACK payloads (also enables dynamic payloads). |
| `RF24_disableAckPayload(radio)` | Disable ACK payloads. |
| `RF24_enableDynamicAck(radio)` | Allow per-packet ACK disabling via `writeMulticast()`. |
| `RF24_writeAckPayload(radio, pipe, buf, len)` | Load a payload to send back on the next ACK for `pipe`. |

---

### Power Management

| Function | Description |
|---|---|
| `RF24_powerUp(radio)` | Wake the radio from power-down mode. |
| `RF24_powerDown(radio)` | Enter low-power mode (~900 nA). Call `powerUp()` to resume. |

---

### Diagnostics

| Function | Description |
|---|---|
| `RF24_isChipConnected(radio)` | Returns `1` if SPI communication with the chip succeeds. |
| `RF24_isPVariant(radio)` | Returns `1` if the chip is an nRF24L01+ (supports 250 kbps). |
| `RF24_testRPD(radio)` | Returns `1` if a signal ≥ -64 dBm was detected (nRF24L01+ only). |
| `RF24_testCarrier(radio)` | Returns `1` if a carrier was detected (nRF24L01 non-+ only). |
| `RF24_flush_tx(radio)` | Flush the TX FIFO. Returns STATUS byte. |
| `RF24_flush_rx(radio)` | Flush the RX FIFO. Returns STATUS byte. |
| `RF24_getStatus(radio)` | Read the STATUS register via a NOP SPI transaction. |

---

### Low-Level Register Access

These are rarely needed directly but available for advanced use:

| Function | Description |
|---|---|
| `RF24_read_register(radio, reg)` | Read one byte from a register. |
| `RF24_read_register_buf(radio, reg, buf, len)` | Read multiple bytes from a register. |
| `RF24_write_register(radio, reg, value)` | Write one byte to a register. |
| `RF24_write_register_buf(radio, reg, buf, len)` | Write multiple bytes to a register. |

## Enumerations

### `rf24_pa_dbm_e` — PA Level

| Value | nRF24L01 | nRF24L01+ (LNA on) |
|---|---|---|
| `RF24_PA_MIN` | -18 dBm | -6 dBm |
| `RF24_PA_LOW` | -12 dBm | 0 dBm |
| `RF24_PA_HIGH` | -6 dBm | 3 dBm |
| `RF24_PA_MAX` | 0 dBm | 7 dBm |

### `rf24_datarate_e` — Data Rate

| Value | Rate |
|---|---|
| `RF24_1MBPS` | 1 Mbps |
| `RF24_2MBPS` | 2 Mbps |
| `RF24_250KBPS` | 250 kbps (nRF24L01+ only) |

### `rf24_crclength_e` — CRC Length

| Value | Description |
|---|---|
| `RF24_CRC_DISABLED` | No CRC |
| `RF24_CRC_8` | 8-bit CRC |
| `RF24_CRC_16` | 16-bit CRC (recommended) |

## `RF24_t` Handle Fields

You should not modify these directly after calling `RF24_init()`.

| Field | Type | Description |
|---|---|---|
| `hspi` | `SPI_HandleTypeDef*` | HAL SPI handle |
| `ce_port / ce_pin` | `GPIO_TypeDef* / uint16_t` | CE GPIO |
| `csn_port / csn_pin` | `GPIO_TypeDef* / uint16_t` | CSN GPIO |
| `status` | `uint8_t` | Last STATUS byte from SPI (updated automatically) |
| `config_reg` | `uint8_t` | Cached NRF_CONFIG register value |
| `payload_size` | `uint8_t` | Static payload size |
| `addr_width` | `uint8_t` | Address width in bytes (3–5) |
| `dynamic_payloads_enabled` | `uint8_t` | 1 if DPL is on |
| `ack_payloads_enabled` | `uint8_t` | 1 if ACK payloads are on |
| `is_p_variant` | `uint8_t` | 1 if nRF24L01+ detected |

## Complete Ping-Pong Example

The example in `main.c` demonstrates a simple two-node system.

Set `#define RF24_ROLE 0` on the **transmitter** and `1` on the **receiver**:

```c
// ── Transmitter (flashes LED on ACK) ──────────────────────────────────────
#define RF24_ROLE 0

static uint32_t counter = 0;
while (1) {
    uint8_t ok = RF24_write(&radio, &counter, sizeof(counter));
    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, ok ? GPIO_PIN_RESET : GPIO_PIN_SET);
    counter++;
    HAL_Delay(1000);
}

// ── Receiver (toggles LED on each received packet) ────────────────────────
#define RF24_ROLE 1

while (1) {
    if (RF24_available(&radio)) {
        uint32_t payload;
        RF24_read(&radio, &payload, sizeof(payload));
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    }
}
```

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---|---|---|
| `RF24_begin()` returns `0` | Wiring error or no power | Check SPI pins, CS/CE, and 3.3 V supply |
| Radio resets or behaves erratically | Insufficient decoupling on VCC | Add 100 µF + 100 nF caps directly at the module |
| TX always returns `0` (no ACK) | Addresses don't match | Ensure TX writing pipe address equals RX reading pipe address |
| 250 kbps fails | Non-plus variant | Use `RF24_1MBPS` or `RF24_2MBPS`; check `RF24_isPVariant()` |
| SPI communication garbled | SPI mode mismatch | nRF24L01 uses SPI mode 0 (CPOL=0, CPHA=0) |
| Only pipe 0 receives | Other pipes not enabled | Call `RF24_openReadingPipe()` before `RF24_startListening()` |
